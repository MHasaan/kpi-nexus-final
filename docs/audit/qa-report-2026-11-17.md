## 2. High severity

### H-1 · Dashboard widgets show the oldest value in the range, and charts run backwards
- **Where:** every custom dashboard (`/dashboards/:id`): KPI card, Number, Gauge, Trend and Line widgets.
- **Repro:**
  1. Open the seeded *Company Overview* dashboard and pick **1y**.
  2. The MRR card shows **392,375**, the oldest point. Actual latest MRR is about **501k**.
  3. On a new dashboard with ARR, **90d** shows 5,828,096 (September) instead of the latest 5,976,000 (October).
  4. The *MRR trend* x-axis reads `28/09/2026 → 28/07 → 28/05 → 28/03 → 28/12/2025`: newest on the left, time running backwards.
- **Cause:** the API returns data points **newest first** (`orderBy periodStart desc`, `apps/api/src/kpis/kpi-data.service.ts:450`). The widgets assume oldest first:
  - `KpiCard.tsx:32`, `NumberWidget.tsx:19` and `GaugeWidget.tsx:38` take `dataPoints.at(-1)`, which is the oldest point.
  - `TrendWidget.tsx:19` uses `slice(-30)`, which picks the oldest 30.
  - `LineChartWidget.tsx:23` plots the array as given.
- **Also:** on **7d / 30d** (7d is the default), monthly KPIs show "No data" because no data point starts inside the window, even though the KPI has a current value.
- **Contrast:** the home overview, the public share page and the PDF report all show the correct latest value, so the same number disagrees across the app.

### H-2 · Approvals page is unusable for non-admins
- **Where:** `/approvals`. It is in every user's sidebar because the nav item has no permission gate.
- **Repro:** sign in as `devon.reyes@helios.io` (Department Manager) or `aaron.cole@helios.io`, then click **Approvals**. You are redirected to **/unauthorized**, although `GET /approvals/requests` returns 200 with 1 pending request for them.
- **Cause (two bugs):**
  1. `apps/web/src/app/approvals/page.tsx:224` wraps the admin-only "Workflow configuration" section in `<RequirePermission permission="ORG_SETTINGS">` with **no `fallback`**. Without a fallback the component redirects the whole page to /unauthorized.
  2. The page loads `listApprovalWorkflows()` (needs ORG_SETTINGS → 403) inside the same `Promise.all` as the requests (`page.tsx:~127`). Even with the redirect fixed, one 403 fails the whole load.
- **Impact:** approvers who aren't admins can't see or decide approval requests. That defeats the approvals feature, since approvers are usually managers.

### H-3 · KPI health is computed two different ways and they disagree
- **Repro:**
  1. Edit a KPI and set Target 100,000, Warning 80,000, Critical 60,000.
  2. Record 72,000.
  3. The **home dashboard** says *At risk, 72%*, while the **KPI page** shows *Threshold status: `no_bands`* and the **Thresholds** and **Targets** tabs say "No bands" / "No targets".
- **Cause:** `apps/api/src/kpis/kpi-health.ts` (home, scorecard, summary) falls back to the KPI's own `warningThreshold` / `criticalThreshold`. `GET /kpis/:id/threshold-bands/status` (KPI page) only reads ThresholdBand rows. The KPI form writes the first and never creates the second.
- **Related front-end bug:** `KpiCard.tsx:22-26` colours a card `value <= criticalThreshold → critical`, which assumes higher-is-better. For a **lower-is-better** KPI (target 2, warning 3, critical 5, value 4) the backend correctly says **AT_RISK**, but the card would colour it **critical**. Every lower-is-better KPI (churn, resolution time, CAC…) gets the wrong colour.

## 6. What was verified working

- **Auth:** login, wrong-password 401, invite email → accept-invitation → login (token can't be reused), forgot password → email → reset → new password works / old fails.
- **Onboarding:** wizard with template, admin creation, auto-login; draft autosave.
- **KPIs:**
  - Create (with browser validation), edit, activate, record value, correction and history, versions, comments, watch.
  - CSV import dry-run (catches duplicates), categories CRUD.
  - Forecast (naive / ARIMA), anomaly detect, what-if, embed tokens.
  - Scope-specific data endpoints return 422 on the wrong endpoint.
- **Dashboards:** create with starter widgets, share link (public page loads), snapshot, set default, delete.
- **Alerts:** rule create through the UI (all 4 rule types switch their fields), escalation with channels; **a breaching value fires the alert immediately**; acknowledge; channels CRUD; email alert delivery.
- **OKRs:** create, add a KPI-linked key result, sync → progress rolls up (67%).
- **Tasks:** create through the dialog; Cancel doesn't submit.
- **Reports:** create, Run now → email with a signed PDF link → valid PDF downloads.
- **Org admin:** invite, roles CRUD + scope patch, positions, org units, settings save, terminology rename reaches the sidebar, invalid settings rejected server-side.
- **Permissions:** every API endpoint refuses unauthorised roles with a clean 403. Admin-only pages redirect non-admins to /unauthorized, and nav items are hidden by permission (except Approvals, see H-2).
- **Search:** finds KPIs, people and dashboards.
- **Status page:** live.

**Not covered:**
- Drag-and-drop on the Tasks board (the synthetic drag didn't register in the test browser, so this is unverified, not known broken).
- Realtime SSE pushes.
- SSO / SCIM / custom domain (need external IdP or DNS).
- Slack / Teams / Jira (need real workspaces).
- Mobile layouts, dark mode and i18n beyond a glance.
