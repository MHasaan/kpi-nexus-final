# 07 — AI Layer (Insights, Recommendations, Ask/NLQ)

Multi-provider AI (Gemini default, with Claude/OpenAI/Ollama fallback) with per-org budget
caps. These pages surface generated content with **trust signals** — provider/model, cost,
confidence, and the sources/data behind each answer. Require `INSIGHTS_VIEW` (insights/recs)
and the relevant view permission for NLQ. Budget exhaustion / provider errors must degrade
gracefully (clear message, never a blank crash).

---

## `/insights` — AI-generated insights

- **Purpose**: narrative insights about KPI performance ("MRR growth decelerated; churn is the driver").
- **Layout**: heading + **Generate** (`insights-generate`); a **list** (`insights-list`) of insight cards — each with the narrative, the KPI(s) referenced (linked), a confidence indicator, and provider/cost metadata; dismiss/keep actions.
- **Data/API**: insights generate + list endpoints (org-scoped, budget-capped).
- **States**: `insights-empty` (CTA to generate), `insights-error` (incl. budget-exceeded → explain the cap + when it resets).
- **Design notes**: cards read like a briefing; cite the data; show "generated by {model} · ${cost}"; let users regenerate.

## `/recommendations` — AI recommendations

- **Purpose**: actionable recommendations (often tied to alerts/KPIs) with accept/dismiss.
- **Layout**: **list** (`recs-list`) of recommendation cards — title, rationale, linked KPI/alert, suggested action (e.g., "create a task"), accept/dismiss; status reflects RecommendationStatus.
- **Data/API**: recommendations list + status update; some are auto-triggered by alerts.
- **States**: `recs-empty`, `recs-error`.
- **Design notes**: each card should make the "so what / now what" obvious; accepting can spawn a Task (link to 08). Confidence + source shown.

## `/ask` — Natural-language query (NLQ chat)

- **Purpose**: ask questions about your KPIs in plain language; get an answer grounded in **your visible data** (RAG over pgvector with **visibility filtering** — users never see data they lack permission for).
- **Layout**: a chat surface — **messages** thread (`ask-messages`), an **input** (`ask-input`) + **submit** (`ask-submit`); each answer shows its **sources** (`ask-sources`: which KPIs/data informed it) and provider/cost; empty state (`ask-empty`) with example prompts.
- **Data/API**: NLQ endpoint (RAG, visibility-safe, budget-capped). Answers may include a chart/table where relevant.
- **States**: `ask-empty`, `ask-error` (provider/budget); streaming/typing indicator while generating.
- **Design notes**: this is the conversational centerpiece — message bubbles, streaming text, source chips that link to the KPI/dashboard, suggested follow-ups. Make the "grounded in your data, respects your permissions" promise visible (sources panel). Could also be reachable from ⌘K.
